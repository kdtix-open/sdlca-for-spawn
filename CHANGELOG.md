# Changelog

This file is for people who use or maintain the SDLCA agent kit, and it records every notable change in plain words. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and the project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html). How we cut a release is in [releasing](docs/contributing/releasing.md).

Nothing has been released yet. The first release is planned as 0.1.0 (the number already in `package.json`), and the section below describes what is in the repository today.

## [Unreleased]

### Added

- **Optional extensions.** `sdlca-ext` is a framework for tools and MCP servers that live outside the kit (the kit ships none). An extension is a folder with a validated manifest; `scaffold`, `validate`, `list`, `enable`, `disable`, `allow`, `mcp-config`, `check` and `run` manage it. Keys come from `accounts/<account>/credentials.d/<name>.env` (0600, nothing expanded, only declared names), either handed to one command by `run` or put in the agent's environment for MCP servers. Permissions are printed, never widened. Guides: `docs/extensions.md` and `docs/optional-tools.md`.
- **Listener.** `sdlca-listen <account>` watches one Spawn account's inbox with the Spawn client's `events` command (chat mentions, friend requests and Savi events), resumes from a saved cursor, and exits with status 78 when `SDLCA_AGENT_CMD` is not set so that systemd does not restart it in a loop. Its `listener.log` keeps the client's status lines, not the events, because the events hold other people's chat text. The systemd unit backs off while the listener keeps failing (5 seconds at first, growing to 5 minutes) and runs with `NoNewPrivileges`.
- **Event handler.** `sdlca-on-chat <account>` runs one agent turn for each allowed chat mention. It renders a prompt, runs your `SDLCA_AGENT_CMD` (any command that reads a prompt on stdin) inside the right world's git clone, stops a hung turn after `SDLCA_AGENT_TIMEOUT` seconds (default 1800), and lets only one turn at a time write to a world. A turn waits for the world's lock for at most `SDLCA_LOCK_WAIT` seconds (default 3600), and the agent does not inherit the lock, so a process it leaves running cannot keep it. An event that names no known world, such as a direct message, runs in `run/scratch/<account>`, never in the runtime home that holds every account's token. The prompt wraps the event in `<untrusted_event>` tags and tells the agent that everything it fetches later is data. Savi events are logged only.
- **Safe by default.** Only the account owner, plus Spawn usernames listed in `allowlist.json`, can trigger work; everyone else is ignored silently and logged by name only. Handles are compared as Spawn writes them (`@name` is a person, `@@name` is an agent), so an agent that shares the owner's name is not the owner. The agent's own handle is denied. The sender and the world come from structured event fields, never from chat text, and a world matches only on a whole id or address (`@alice/game` never matches `@alice/game-2`). Friend requests are accepted only from the owner. Tokens live in files with mode 0600 and are passed to `curl` on stdin, never on a command line. The kit sends a token only to the one origin in `SPAWN_ORIGIN` (default `https://www.spawn.co`), which must be https (plain http only to this machine) and must not contain user information, and it never follows a redirect. The raw token that the Spawn client hands to the handler is removed before the agent starts. The kit's own log lines hold metadata, not chat text (the agent's output also goes to `handler.log`, so keep it private).
- **Careful with odd input.** A second security review added these checks. `sdlca-api` refuses a JSON body that starts with `@`, because curl would read that local file and send it to Spawn, and the kit's `curl` calls ignore `~/.curlrc` and do not expand `[1-3]` or `{a,b}` in an address. A token with a space, line break, quote, backslash or any character that is not visible ASCII is refused when the kit sends it, when `sdlca-say` or `sdlca-worlds` reads it and when `sdlca-token add` stores it, and the error never prints it. `sdlca-look` accepts only a world written as `@owner/world` or `@@agent/world`, and writes only a new `.png` under `/tmp`, `$TMPDIR` or `$SDLCA_SPAWN_HOME/shots` (no `..`, no link, not a folder). `sdlca-listen` quotes the handler command for the shell that runs it. `scripts/install.sh` refuses a kit folder name with a space or a character that is special to systemd or `sed` (letters, digits and `. _ / + @ : -` are fine). `sdlca-worlds` skips owner or world names that start with `.` or `-`, and stops without changing anything when `worlds.json` exists but is not a valid JSON object, so it never overwrites a registry it cannot read. `sdlca-allow` refuses an id or name that ends in a line break. `sdlca-say` always allows at least 2 lines, ignores a `Retry-After` that is negative, not a number or infinite, and accepts `replyTo` only as ASCII digits. Routing skips a damaged world entry instead of failing every event, a damaged `handled.ids` or `runs.log` is read leniently, and the inbox cursor is locked while it is read, compared and written, so two handlers that finish together cannot move it backward.
- **Reliable delivery.** The inbox cursor only moves forward and is written atomically, so a restart resumes after the last handled event. Delivery is at-least-once, but an event id that already finished is skipped (`accounts/<account>/handled.ids` keeps the newest 500). A turn that fails, times out, waits too long for the world's lock or is refused by the hourly cap is kept in `run/failed/<event-id>.json`, and the cursor moves past it; replay it by hand with `SPAWN_EVENT="$(cat run/failed/<event-id>.json)" sdlca-on-chat <account>`. A saved event holds the chat text, so the handler deletes saved events that are more than `SDLCA_FAILED_KEEP_DAYS` days old (default 30; `0` keeps them forever). It does this when the next allowed event reaches the handler, so replay a failed turn before then or copy the file. An account starts at most `SDLCA_MAX_RUNS_PER_HOUR` agent turns an hour (default 20; 0 turns the cap off).
- **Two copies of one event.** If two copies of the same event arrive together, the agent runs once: the handler checks again after it takes the world's lock, and records the event id while it still holds the lock (the log says `SKIP event <id> was already handled (another copy finished first)`). The numbers 74, 75 and 76 are the handler's own exit codes, so an agent command that exits with one of them is logged as a failed turn (status 1). `EVENT`, which holds the chat text, is never in the agent's environment, even if the caller exported it. If the hourly cap cannot be checked (the setting is not a number, or `runs.log` cannot be written), the handler logs an error and leaves the event unhandled. If `handled.ids` cannot be read, it logs a warning and treats the event as new, because a repeated turn is better than a lost one.
- **The clone is brought up to date before each turn.** For an event that matched a world, `sdlca-on-chat` now runs `lib/refresh.py` while it holds the world's lock and before the agent starts. It fetches the checked-out branch, from the git address that `sdlca-worlds` recorded for the world (see the next entry), into a ref of its own (`refs/sdlca/refresh-tip`, with no `FETCH_HEAD`) and into the tracking branch the clone follows, and moves the branch forward only when that is a straight line (`git merge --ff-only --no-overwrite-ignore`). It never makes a merge commit, never rewrites history, never leaves conflict markers and never overwrites a change you have not committed, an untracked file or an ignored file. In every other case it changes nothing and says why (`unverified`, `ahead`, `diverged`, `detached`, `no-upstream`, `untrusted`, `not-git`, or `fetch`, `timeout`, `merge` and `error` when something failed). The kit does this itself because it cannot tell a read-only agent, which cannot run git, from a building one, and because a plain `git pull` can make a merge commit or stop with conflict markers in files the world runs. The handler logs one `WORLD <address> clone <status>/<code>: <text>` line and ends the prompt with a paragraph, in fixed wording, that says whether the clone is current: nothing that git said or a remote can influence is put in the prompt. A direct message has no world and runs no update. A missing, crashed, stopped or timed-out update never fails the turn, and a crash puts its traceback in the log. `SDLCA_REFRESH_TIMEOUT` is the number of seconds each git call may take (default 60; `0` turns the update off, even when `lib/refresh.py` is missing). The fast-forward gets at least 600 seconds, because a checkout that is stopped half way leaves a half-updated work tree, and the handler stops the whole update after four times the value plus 660 seconds. A call that runs out of time is stopped with everything in its process group, `SIGTERM` first so that git removes its own lock files. The update needs git 2.29 or newer and runs before `SDLCA_CREDENTIALS_FILE` is read, so provider keys are never in its environment. The clone is a folder the agent may have written to, so the update runs git without a shell and only through absolute `PATH` entries, with hooks and the file system monitor turned off on the command line, https only, no prompts, a fixed commit identity and none of the variables that redirect git. It reads the clone's own configuration before the fetch and again before the fast-forward and refuses a clone that can run a program or send git elsewhere (`filter.*`, `core.fsmonitor`, `include.*`, `url.*.insteadOf`, a proxy, every `http.*` key that can move a request or change whom git trusts, a credential helper that is not the one `sdlca-worlds` writes for one of the kit's token files or that is scoped to another origin than the world's recorded address, and more), and one with a link under `.git/logs` or `.git/refs`, where git would write through it. That check is a list, so it cannot cover everything: see [the security model](docs/security-model.md#updating-the-clone-before-a-turn). The default prompt no longer tells the agent to run `git pull`. It says that the kit updates the clone of the world a message came from, and that any other clone may lag the latest push. It also gains a rule: never force-push; if a push is rejected, run `git fetch`, then `git rebase --fork-point origin/main` (a plain rebase can bring back commits that the world removed), check that the change still works and push again, or stop and tell the person if a conflict cannot be resolved. A prompt override you made earlier does not get these lines, so copy them in.
- **A look waits for the world to load.** The first real run of `sdlca-look` on a real machine (software rendering, no graphics card in use) produced a black picture every time: the renderer draws nothing until the world has loaded, which took about a minute and a half, and the tool took one picture after 8 seconds. It now takes the first picture after `wait-seconds`, and while a picture is blank (under 20000 bytes) it waits `SDLCA_LOOK_POLL` seconds (default 10) and tries again until the time limit; when a real picture came only after blank ones it waits `SDLCA_LOOK_SETTLE` seconds (default 20) for the scene to fill in and takes one more. A picture that takes too long is skipped and tried again; if every picture is blank when the time runs out, the look fails and says so. The default `SDLCA_LOOK_TIMEOUT` is now 240 seconds (it was 120), so the body's own end of life is 270. The handler prompt tells the agent that a look can take two to four minutes and to give that call a long timeout. See [Seeing a world with sdlca-look](docs/configuration.md#seeing-a-world-with-sdlca-look).
- **A stray `SPAWN_TOKEN` can no longer change which account a command runs as.** Spawn's client reads `SPAWN_TOKEN` before the account's token file, so a `SPAWN_TOKEN` left in someone's terminal (a personal token used for a test) made `sdlca-look` and the other tools that start the client run as that person, which the client refused with "this account is a person's". Every tool that takes an account now removes the variable when it loads the account, and an env file cannot set it either.
- **A body for an agent.** `sdlca-body <account> <picture>` makes a rigged 3D body from a picture of your own and puts it on an agent account, through Spawn's published character doors: it uploads the picture as a draft, starts the sculpt, waits for it and wears the result. It does nothing until you add `--apply`, and a dry run only reads from Spawn. It refuses an account that is not an agent and a file that does not start like a PNG, JPEG or WebP picture of at most 4 MB (the file's own bytes decide, not its name). The picture goes as it is, under a fixed file name, so your file name and folders are not sent, and the plan names embedded text or camera data and any bytes after the end of the picture. A second paid sculpt is what it is built to prevent: no call that makes something is repeated; just before the sculpt is asked for, the tool records it in `body-sculpt.json` in the account's folder, and while that file exists a picture run for the account refuses; when the answer to the request for the sculpt is lost or unclear it says that the sculpt may have started and keeps the record; and once the sculpt exists, every way the run can stop (a refused or failed wear, Ctrl-C, a closed terminal) prints the `--job <id>` command that carries on, as does a wait that runs out (exit status 3). `--wear <address or look>` puts a body that already exists on an agent, `--reset <characterId>` takes a made body off, and `--carry <file.glb> --world <@owner/world>` carries a model file to Spawn through a world's asset doors (a big file by address, with no token on the storage request, and the signed storage address is never printed). The tool refuses to run inside an agent turn. The token goes only to Spawn's own origin, never through a proxy for a plain-http origin, and is taken out of everything the tool prints; no call lasts longer than two minutes, however slowly Spawn answers. [`tests/test_body.py`](tests/test_body.py) covers it against a stand-in Spawn, and real runs on 2026-11-19 and 2026-11-20 made and wore a body in about four minutes, undid it and re-wore it from the same finished sculpt (no new sculpt), carried a 5.2 MB model by address, and wore the carried address as a body for one join. Spawn refused the same address as a second agent's profile body (`body_not_carried`), so that agent still needs a sculpt of its own. Do not put the command on an agent's list of allowed commands: see [Why an agent must not run sdlca-body](docs/security-model.md#why-an-agent-must-not-run-sdlca-body). `lib/safeurl.py` has a new option, `opener(direct=True)`, that ignores the environment's proxy settings. `sdlca-body`, `sdlca-say` and `sdlca-worlds` use it for a plain-http origin (this machine, for tests and development): a proxy named in the environment could have received the token, in clear text, for that origin. Each tool has a test with a decoy proxy.
- **A look can stand at a position and face a point.** `sdlca-look ... --at <x,y,z> --face <x,y,z>` stands the body's feet at a world position (the Spawn client's `exec`, a run that saves nothing, read back with `where`) and turns the camera from the eye (feet plus 1.6 m) toward a world point, so a Try Walk spot and its "what to look at" can be handed straight to a look. In this engine yaw 0 faces -z. The turn is made from the page's edge so that up to about 170 degrees fits in one sweep. Run for real against `@lanthief/game-1` on 2026-11-22: the body reached about 0.4 m from the asked spot (the world's colliders move it), the camera reached the asked yaw within 3 degrees, and the picture showed the box that a default look never showed.
- **A placed body says it is being looked through.** After `--at` stands the body, the look sets `state.lookHold` on it (a `ctx.now()` stamp). A world's script that moves idle bodies can honor that; `@lanthief/game-1`'s doorway habit does (it held the body on the arrival ring only after Savi added the flag, on 2026-11-22). A world that does not read it ignores it.
- **A look reads a pinned spot from a card file.** `sdlca-look ... --spot <card.json>` takes the stand point and the face point of the first spot that has a `face` (a Try Walk pin saves exactly those two points), so nobody retypes coordinates. The file must be a plain file of at most 64 KB and cannot be mixed with `--at` or `--face`.
- **One look at a time per account.** A look waits for another look of the same account (up to its time limit) instead of fighting it over the client's join, which gave "join failed" and "connection refused" and no picture.
- **A look that cannot stand where asked fails plainly.** If `--at` leaves the body more than 2 m from the asked spot (numbers that were local to a parent, not world metres, once put an agent at y -76), `sdlca-look` takes no picture, exits with status 4 and says what the body's position is and what the numbers must be.
- **Uploading a finished model.** `sdlca-asset <account> <@owner/world> <model.glb>` carries a .glb (a prop needs no skeleton) to the world's assets through Spawn's documented asset door and prints the `/cdn/` address that a scene points at. It is the one body-tool path an agent turn may use, for its own account only, and it changes no body. A world keeps models out of its git files, so the arrival budget is untouched.
- **Sharper looks.** `SDLCA_LOOK_WIDTH`, `SDLCA_LOOK_HEIGHT` and `SDLCA_LOOK_RENDER` pass the frame size and the renderer to the client's join. At 1280 x 720 the software renderer gave a picture an agent can read; the graphics card gave blank pictures on the test machine.
- **The camera can be aimed.** `sdlca-look ... --yaw <degrees> --pitch <degrees>` takes the pointer lock like a player, moves the mouse, measures each turn with Spawn's `where` and corrects it, then takes the picture (it takes it even if the aim could not be reached). Real runs reached yaw 1 and pitch 0 for a target of 0, and once stopped 26 degrees short, so treat the aim as close, not exact. Only documented client behavior is used.
- **Each world has its own ledger, and the agent no longer reads the runtime home.** The ledger is `<clone>/.sdlca/WORK-TODO.md`, made by the handler when a turn starts, ignored by git through `.git/info/exclude` (so it is never pushed) and never written through a link. The kit's standing notes (`AGENTS.md` in the runtime home) are put in the prompt by the handler. The prompt no longer sends the agent to read files under the runtime home, which also holds the tokens. `/spawn ... then <request>` joins and then runs the agent with the request.
- **Presence commands in chat.** The owner can mention the agent with `/spawn` (the agent's body joins the world the message came from for `SDLCA_PRESENCE_TTL` seconds, 3600 unless set), `/spawn ttl <seconds>` (10 to 14400) or `/leave`. The kit does it itself, with no agent turn, no model and no permission to grant: `lib/command.py` accepts the owner's line only when it is exactly the command (leading @mentions are dropped), so a longer sentence, an allowed sender or another account's line goes to the agent as before. The client's output is discarded because a join can print a credential, and a second `/spawn` replaces the first. Covered by `tests/test_command.py` and `tests/shell/test_on_chat.sh`.
- **One body ships with the kit.** `templates/bodies/kdtix-agent-body.glb` is a finished rigged body (a silver robot with the KDTIX open-source gear mark) that Spawn sculpted from a KDTIX picture. A maintainer decided on 2026-11-20 to ship this one file and no other generated model until the question has been reviewed further; `tests/test_shipped_body.py` fails if another model file is added. Its [README](templates/bodies/README.md) says where it came from and what is inside (a skeleton, five named animation clips and processing notes that come from Spawn's pipeline, whose terms have not been reviewed). Spawn was not asked. Today it works as a body for one join, not as an agent's profile body.
- **The issue forms show the safe Claude Code command.** The two example commands in the bug report and agent behavior forms now carry `--setting-sources user`, as every other example in the kit does (without it, Claude Code in print mode runs a world's own project settings).
- **The clone is held to the git address that Spawn gave for the world.** The update used to fetch from whatever address the clone's own configuration named, so an agent that could edit `.git/config` could point the fetch, and an account's token, at a host of its choosing. Now `sdlca-worlds --apply` records, outside the clone, the git address from Spawn's own listing (the `git` field of the world in `worlds.json`, only when it is https with a host and no user information, the form the clone's credential helper can be attached to; one that is not usable is not recorded and a stale one is removed, and the tool prints the host, never the address). `lib/route.py` prints it as a new last field, `sdlca-on-chat` passes it to `lib/refresh.py` as a second argument, and the update fetches from exactly that address (`git fetch -- <address> ...`, not through the name of a remote, so the settings of the remote that the branch follows do not apply; a remote section that is called like the address would be read as that remote by git, so such a clone is untrusted) and only when the clone agrees: the branch's remote must have one address and it must be the recorded one (scheme and host compared in lower case, a trailing slash or `.git` ignored, the port and the rest of the path as written, no user information, no `.` or `..` segment), or the clone is `untrusted` and the log names hosts and never a whole address. A credential helper must now be scoped to the origin (scheme, host and port) of the recorded address, and one scoped to any other origin, even an empty one, makes the clone untrusted. A world with no usable recorded address gets the new answer `skipped/unverified`: no git runs, the turn still runs, and the prompt says in fixed words that the address has not been recorded and that the person can run `sdlca-worlds --apply`. The fetch also writes the tracking branch the clone's own fetch rule names, in the same fetch, because a fetch from an address does not and the reflog of that branch is what `git rebase --fork-point` and the check for a world that moved back read. A world recorded before this entry has no address: run `sdlca-worlds --apply` under the agent's account, with `--only @owner/world` for one world, and look at the dry run first (it never changes the clone). `lib/gitcred.py` now holds the one parser for a git address that `sdlca-worlds` and `lib/refresh.py` share. The clone's settings are now checked before git reads any object and not only before the fetch, because reading a missing commit makes git fetch it from a promisor remote that the settings name, with the token if a helper is scoped to it (`extensions.partialClone`, `remote.<name>.promisor`, `remote.<name>.partialCloneFilter` and `promisor.*` are on the list, and every git call carries `GIT_NO_LAZY_FETCH=1`). An address with a `.` or `..` segment is not recorded, by the same rule that the update uses, and a rename moves the clone's remote only to an address that is recorded. What is still open, and written down in [the security model](docs/security-model.md#updating-the-clone-before-a-turn): an agent that can edit `worlds.json` or the runtime home, or can run a program as your user, can change the record; the check of the clone's settings is still a list, made at three moments, so a program that outlives the turn can change the file between the check and the fetch (a few tries are enough); a separate Unix user for the agent is still the real boundary. The tests show the attack (a clone rewritten to point at a server on this machine, with a copy of the kit's helper line scoped to it) sends that server nothing, with controls that show the earlier logic and plain git would have connected and handed over the token.
- **Commands.** `sdlca-onboard` (create or re-link an agent account), `sdlca-token` (store and check a Spawn token without it ever appearing on a command line: `init`, `add`, `path`, `verify` and `list`), `sdlca-friends` (accept the owner's friend request), `sdlca-say` (post a reply, split into numbered 200-character chat lines sent 2.2 seconds apart, at most `SDLCA_SAY_MAX_LINES` of them (default 8), retrying on rate limits and server errors), `sdlca-worlds` (keep `worlds.json` and the local clones in step, following renames; dry run unless `--apply`), `sdlca-as` (run a command with one account's environment), `sdlca-api` (call the Spawn API with an account's token), `sdlca-allow` (edit the allowlist) and `sdlca-look` (save one screenshot of a world; the camera does not turn toward objects yet).
- **Worlds an agent made.** `sdlca-worlds --apply` records which accounts can reach each world (`--only @owner/world` limits a run to the worlds you name, which matters for a personal token that reaches many; each line shows your standing in the world; a personal token gets a note and `--apply` then needs `--as-person`), so a world an agent made itself (`@@agent/world`) is served too. A clone that is missing is tried again on every run, an existing clone is never modified, and a folder move after a rename waits while an agent is working in that world. Clones the kit makes use the commit identity `sdlca-agent` unless you set `SDLCA_GIT_NAME` and `SDLCA_GIT_EMAIL`.
- **Grouped accounts and `sdlca-token`.** An account name may be one word or `group/name` (each word lowercase letters, digits, underscore or hyphen, starting with a letter or digit), and its files live in `accounts/<group>/<name>/`. `sdlca-token add` asks for the token without echoing it (or reads one line from stdin with `--stdin`), refuses invite codes (`sbk_...`) and values that cannot be tokens, and stores the token atomically with mode 0600. `sdlca-token verify` asks Spawn who the token belongs to, and says plainly when it signs in as a person and not as an agent. Grouped accounts are for scripts and tools: a systemd listener instance name cannot contain a slash, so listeners use one-word names. A personal token acts as the person who made it, so each person should make and keep their own; for someone else's account, prefer a separate agent account linked with that person's one-time invite (`sdlca-onboard`). People make personal tokens by hand on their own Spawn settings page; the kit never uses or stores browser cookies.
- **Your git settings stay yours.** The kit never changes your global git configuration (`sdlca-onboard` puts back the credential helper that `spawn login` adds there). Each clone the kit makes gets its own credential helper tied to that account's token file and attached to the git host of the world's https address only, so a remote, submodule or large-file address on any other host gets no credentials.
- **Read-only with sight, and a screenshot tool that is safe to allow.** `templates/account.env.example`, `docs/configuration.md`, `docs/getting-started.md` and `docs/security-model.md` have a fourth posture, the read-only helper plus the rule `"Bash($SDLCA_CODE_DIR/bin/sdlca-look *)"`, and the security model says what allowing `sdlca-look` means: the agent's body is in the world, visible to every player in the room, for the length of a look; it counts against the account's body budget; the picture goes to your model provider; text in the world can try to steer the model; and the join credential is never printed. To make that safe, `sdlca-look` now refuses a world that the account does not serve (the address, or an old address of a renamed world, must be listed for it in `worlds.json`, by the rule in `lib/route.py`, which has a new `--serves` mode; the message says to run `sdlca-worlds --apply --only` first); inside an agent turn it refuses any account but the turn's own (`sdlca-on-chat` sets `SDLCA_TURN_ACCOUNT` for the agent command only, and no file can change it); it stops at `SDLCA_LOOK_TIMEOUT` seconds (default 240) for the join and the pictures together, so a hung join cannot hold a turn; however it ends, it leaves the world and, on Linux, stops a browser that the join left behind (it finds it by the page's port, and only when that program began after the look did); it takes the page address only from the client's own `page :` line, so an address in a player's name or a chat line cannot point the screenshot at another program on the machine; and nothing the client prints is shown or stored. It starts the client and the screenshot tool in a private, empty folder and not in the agent's clone, because bun loads a `bunfig.toml` (whose `preload` runs code) and a `.env` from the folder it starts in, and a clone that other people can push to could hold either; the picture is made in that folder and placed at the output as a new file that never follows a link (an output that exists already is refused, and a link planted while a look runs is not written through); it prints `saved <path>` on success; and the page address is written down as it comes, so a join that stays alive after its page line is stopped together with its browser. A damaged `worlds.json` is reported as damaged, and an old address that another world has as its current one finds the world that has it now. `sdlca-look --check [account]` joins nothing, uses no network and says what is missing, with a fix (a browser found only in Playwright's cache is shown as `unsure`). The prompt now tells the agent to say so under `Handler notes:` when a look is refused or not permitted, and to say which picture it describes. `docs/operations.md` has a troubleshooting section for it. A prompt override you made earlier does not get the new lines in "Seeing the game": copy them in (see "The prompt override" in `docs/configuration.md`).
- **A world's own project settings no longer run code when the agent runs in print mode, if the agent command passes `--setting-sources user`.** In print mode (`-p`) Claude Code skips the question about trusting a folder, and with default settings it loaded a world's `.claude/settings.json` (hooks) and `.mcp.json` (MCP servers), which anyone who can push to a world can add: on 2026-11-18, with Claude Code 2.1.327, both ran a command as the user before any tool rule applied. Every Claude Code example in the templates and the docs now passes `--setting-sources user`, which stopped both in the same test, and `tests/test_claude_examples.py` fails when an example lacks it. **Action needed for an account you set up earlier:** `scripts/install.sh` never overwrites an env file, so its `SDLCA_AGENT_CMD` still lacks the option until you add `--setting-sources user` right after `-p` (in each `accounts/<account>/env`; it applies to the next event, with no restart). The kit does not check the command, and `docs/operations.md` (Upgrade the kit) says the same. `docs/security-model.md` explains the hole, the facts and their date, the stronger `--restricted` option and why it is not in the examples, that other tools may have the same problem, that older versions may lack the option, and that whether Claude Code still reads a world's own `CLAUDE.md` under the option is not settled (reviewers' runs did not load it, with or without the option), while a world's `AGENTS.md` and any file the agent reads can steer a model whatever the option says. `docs/configuration.md` also has a tip to pin the model with `--model`, because an account's default model can reach its usage limit and the agent then fails every turn.
- **Starter files.** `templates/` holds the agent prompt (which tells the agent it is not Spawn staff), a runtime guide, a work ledger, an allowlist and an account env example. `scripts/install.sh` checks your tools, prepares the runtime home, installs the Playwright library that screenshots use, and installs a systemd user unit for the listeners.
- **Slack example.** `slack/manifest.yaml` and `slack/env.example` show a possible Slack app setup. The Slack bridge itself is not built.
- **Tests.** Python unit tests and shell tests, all run by `bash tests/run.sh` (run it for the current numbers). They use shims for `curl`, `spawn`, `bun` and `systemctl`, a loopback server and local git repositories, so they need no internet, tokens or accounts. They also cover the saved-event cleanup, the state files (`handled.ids`, `runs.log` and token files), the secret scanner, `sdlca-api`, `sdlca-look`, the quoting in `sdlca-listen`, the folder-name check in `scripts/install.sh`, the GitHub setup scripts (against a fake `gh`), a direct run of the Python commands and the update of a world clone (real git in temporary folders, with positive controls for the security tests). The shell tests set `HOME`, `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL` and related variables to a throwaway folder, so a run never touches your real git or systemd files.
- **Checks and automation.** `scripts/lint.sh` has nine steps: `bash -n`, a Python compile check, shellcheck, yamllint, actionlint, `scripts/check-secrets.sh`, a check that `LICENSE` is the unmodified Apache-2.0 text, `scripts/check-links.py` (relative links and heading anchors in the Markdown) and the tests. The secret scanner looks in the files git would commit for Spawn tokens and invite codes, Slack, GitHub, GitLab, OpenAI, Anthropic, Google, AWS, Hugging Face, npm and Stripe keys, Slack webhooks, JSON Web Tokens, passwords inside URLs, provider keys assigned in a file, and private keys. A deliberate test fixture can carry the comment `check-secrets:allow`. The length limits for Spawn's own token formats are guesses, because Spawn does not publish them. `.gitignore` also keeps env files, key and credential files, `handled.ids`, `runs.log` and local tool settings out of commits. The rest of the automation is a GitHub Actions workflow that runs `scripts/lint.sh` on every push and pull request, a pull request labeler, a monthly reminder issue to re-check Spawn's terms, Dependabot updates, release-note categories, and `scripts/setup-github.sh`, `scripts/setup-project.sh` and `scripts/seed-starter-issues.py` (a dry run by default; the starter issues are posted only when a person runs it with `--apply`) for repository setup.
- **Community files.** Apache-2.0 license, README, `docs/`, contributing, conduct (the Contributor Covenant 2.1, which its authors release under CC BY 4.0), governance, security and support documents, issue and discussion forms, and a pull request template.
